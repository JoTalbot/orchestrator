# Agent Jo — автономный драйвер проектов в ChatGPT

Работает вместо Jo: открывает ChatGPT под его аккаунтом, в папке проекта
стартует новый чат (как Jo делал в предыдущих чатах) и ведёт проект до
готовности, анализируя, что происходит в чате. Если чат остановился — пишет
в чат в стиле Jo от его имени. Если контекст разросся — пересоздаёт чат в
той же папке проекта и продолжает.

## Как это устроено

```
jo_driver.py ──> chatgpt_ui.py ──> cdp.py ──> Chrome (docker, CDP :9222)
     │                                     └─ вкладка chatgpt.com (сессия Jo)
     ├─ repo_state(): git/ROADMAP/STATUS проекта
     ├─ jo_style.py: шаблоны сообщений в стиле Jo + эвристики решений
     └─ state_*.json: id чата, циклы, хвост последнего ответа
```

Почему браузер, а не API: POST /backend-api/conversation требует
proof-of-work + Cloudflare turnstile (для дата-центровых IP), которые умеет
решать только настоящий браузер. Поэтому драйвер печатает сообщения в
веб-интерфейсе ChatGPT через CDP — это ровно то, что делает Jo руками.

## Цикл драйвера

1. Читает состояние проекта (git log, ROADMAP-задачи без «Implemented», STATUS).
2. Если чата нет — **находит существующую папку проекта** (реестр
   `projects_registry.json` → сайдбар ChatGPT; новые папки НИКОГДА не
   создаются) и стартует в ней новый чат сообщением INIT в стиле Jo
   (проект, ссылка, GitHub-токен, инструкции).
3. Если чат есть — переходит в него и анализирует последний ответ ассистента:
   - вопрос/просьба решения → «Да. Делай всё сам.»
   - упоминание ошибок → «Продолжи. Ошибки чини сам.»
   - «готово/выполнено» → «Статус. Что сделано, что дальше. Кратко.»
   - иначе → **«+»** (как Jo: продолжай работу, не останавливайся)
4. Ждёт завершения хода (кнопка stop исчезла, текст стабилизировался).
5. Если сообщений на экране > порога — пересоздаёт чат в той же папке
   проекта с handoff-сообщением (состояние + задачи).
6. Пауза между циклами (--cycle-delay), лог каждого шага на русском.

## Запуск

```bash
cd /opt/orchestrator
# разовый тестовый цикл (папка найдётся сама по имени проекта)
.venv/bin/python agent_jo/jo_driver.py \
  --project ukraine \
  --repo-path /opt/orchestrator/projects/ukraine --once

# постоянно: systemd-юнит (пример — agent_jo/jo-agent-ukraine.service)
sudo systemctl enable --now jo-agent-ukraine.service
journalctl -u jo-agent-ukraine -f
```

`--project-url` можно не указывать: драйвер ищет существующую папку по
имени проекта сначала в `projects_registry.json`, затем в сайдбаре ChatGPT.
Реестр обновляется автоматически. Папки не создаются.

## Требования

- Chrome с залогиненной сессией ChatGPT, CDP-порт (на этом сервере:
  docker-контейнер `liza-browser`, порт 9222; профиль = профиль Jo).
- `.secrets/github_pat.txt` — GitHub PAT для передачи агенту в чате
  (Jo всегда даёт доступы в чате; файл 600, в git не попадает).
- `.secrets/chatgpt_token.txt` — для API-проверок (опционально).

## Файлы

- `jo_driver.py` — цикл, состояние, чтение репозитория.
- `chatgpt_ui.py` — управление веб-интерфейсом (ввод/отправка/чтение).
- `cdp.py` — минимальный CDP-клиент (page-level websocket; browser-level ws
  у Chrome один на процесс и занят другими сервисами).
- `jo_style.py` — шаблоны в стиле Jo + эвристики решений.
- `state_{project}.json` — состояние (gitignored).
